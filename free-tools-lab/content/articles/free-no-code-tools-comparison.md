コードを書かずにアプリやWebツールを作れるノーコードは、アイデアを形にする入口として人気です。多くのサービスに無料プランがあります。ただ、**無料で作れること**と、**無料で公開して商用サービスとして運営できること**は、別の話です。この記事では、日本の学生が費用をかけずに試作するために、8つのサービスの無料プランを公式情報をもとに比べます。

:::warning この記事の情報について
無料の範囲、ユーザー数、AIクレジット、公開の条件、ブランド表示、料金は、変更されることがあります。内容は2026年10月4日時点の公式情報に基づいています。「未確認」と書いた項目は、確認できた範囲では明記が見つからなかったもので、可能・不可能のどちらとも断定していません。始める前や公開の前に、必ず公式ページを確認してください。
:::

## 結論：ノーコードの無料プランは「試作」に強い

- 今回の条件（継続して無料、商用利用に対応、無料トライアルは除く）で、**外部の顧客向けアプリを恒久的に無料で公開できると公式に確認できたサービスは、調査の範囲では見つかりませんでした。**
- Bubble、Adalo、FlutterFlow、WeWebなどは、無料で試作やテストをする価値があります。ただ、本番の公開や商用運用は、有料化、別のホスティング、規約の確認が必要になる可能性が高いです。
- 学生におすすめなのは、**個人情報を扱わない小さな試作と、アイデアの需要検証**です。

## 「無料」で何ができるかを分けて見る

| 段階 | 意味 | 無料プランで可能か |
| --- | --- | --- |
| 作る | 画面やデータを設計する | 多くのサービスで可能 |
| テストする | 自分や少人数が動かして確かめる | 多くのサービスで可能（人数などの上限あり） |
| 公開する | 一般に見られる形にする | サービスによる。ブランド表示や上限がある場合も |
| ストアで配信する | App StoreやGoogle Playに出す | 無料では難しい（例：Adaloは有料プランから） |
| 商用で運営する | 顧客に提供する、販売・広告・決済を行う | 多くは有料プランや規約の確認が必要 |

## 気をつけたい「無料トライアル」との違い

- **Softr**：Freeは永久無料ですが、新しく登録するとBusinessプランの7日間の無料トライアルが始まります。トライアル中に見えた機能は、Freeの機能とは限りません。**トライアルが終わってFreeに戻った状態で**、アプリが使えるか確認しましょう。
- **Bubble**：Starterプランには14日間の無料トライアルがありますが、継続無料のFreeとは別です。
- **AppSheet**：無料の使い方は「個人・非ビジネス」「本人利用」「最大10人のテスト」などの条件つきです。
- **Thunkable**：有料プランからFreeに戻すと、有料のときに作ったプロジェクトは読み取り専用になり、長く使っていないと削除される可能性があります。

## サービスごとの向き・不向き

- **Bubble**：画面、データベース、ワークフロー、APIを組み合わせたWebアプリの試作に向きます。重いワークフローや外部のAPIは、使用量や外部の料金に影響します。
- **Glide**：読書記録、学習記録、在庫、タスクなど、**自分だけ、または少人数で使う記録アプリ**に向きます。月0 updatesの意味を理解して、外部のデータを頻繁に更新する使い方は避けましょう。
- **AppSheet**：Googleスプレッドシートをもとにした個人用のツールや、最大10人のテストに向きます。
- **Softr**：ポータル、一覧、フォーム、管理画面の試作に向きます。カスタムドメインは有料プランの機能と案内されています。
- **FlutterFlow**：モバイル・Web・デスクトップの画面を視覚的に試作したい人向けです。重要なプロジェクトを作る前に、バックアップとコードの書き出し、公開の条件を確認しましょう。
- **Thunkable**：ブロック型でスマホアプリの画面や操作を学びたい人向けです。無料のプロジェクトは公開になるため、**機密のアイデア、個人情報、APIキーを入れないでください。**
- **Adalo**：クレジットカードなしで、画面とデータの試作ができます。ストアで配信するには、Adaloの有料プランに加えて、AppleとGoogleの開発者アカウントの費用も別にかかります。
- **WeWeb**：WebアプリのUIを試作して、WeWebのサブドメインで少人数に見せたい人向けです。ブランド表示と月500セッションの上限を受け入れられるテスト用途に限りましょう。

## 目的別の選び方

| 目的 | 候補 | 先に確認すること |
| --- | --- | --- |
| まず1回ノーコードを体験したい | Adalo、Bubble、Thunkable | 公開範囲、Freeの上限、データ保存 |
| 個人の記録アプリを作りたい | Glide、AppSheet、Softr | ユーザー数、更新回数、データの行数、非ビジネスの条件 |
| Webアプリの仕組みを学びたい | Bubble、Softr、WeWeb | 商用公開、ブランド表示、セッション上限 |
| スマホアプリを試作したい | Adalo、Thunkable、FlutterFlow | ストア公開の費用、公開とプライベートの条件 |
| 将来、商用サービスにしたい | Bubble、FlutterFlow、Softrで試作し、コードへの移行も検討 | 本番プランの料金、商用の規約、データの移行 |
| データを外部に置きたくない | ローカルでのコード開発を優先 | ノーコードの多くはクラウド保存が基本 |

## 最短で試す手順

:::steps 小さな試作の流れ
1. 解決したい問題を1つ選びます。例：学習時間の記録、作品アイデアの管理、イベントの準備リスト。
2. 利用者を「自分だけ」に決めます。外部公開、決済、ログインは後回しにします。
3. 公式ページで、無料の条件を確認してからサービスを1つ選びます。
4. **架空のテストデータを10件**だけ入れます。実在の個人情報や機密情報は使いません。
5. 画面は3〜5個以内にして、入力、一覧、詳細を作ります。
6. パソコンとスマホで自分で使い、困った場所を記録します。
7. データをCSVなどでバックアップできるか、公開URLが誰に見えるか、無料枠がどこまでかを確認します。
8. 他の人に見せる前、商用にする前に、利用規約、商用の可否、ユーザー数の上限、ブランド表示、データの削除条件を、もう一度確認します。
:::

## 無料枠を使いすぎない工夫

- テストデータは10〜30件から始める。
- AI機能、外部API、メール送信、自動化は、最初から有効にしない。
- 動画や高解像度の画像を、アプリの中に大量に置かない。
- 無駄な画面、ワークフロー、データの更新を増やさない。
- 外部のユーザーを招待するのは、最後にする。

## 学生が安全に試作するための注意

- ノーコードのアプリは、フォーム、データベース、共有リンクを簡単に作れるぶん、**個人情報を意図せず公開しやすい**です。最初は、架空の名前、テスト用のメールアドレス、ダミーのデータを使いましょう。
- 公開URL、編集URL、管理画面、共有設定を区別します。リンクを知っている人全員が見られる設定になっていないか確認してください。
- APIキー、トークン、パスワード、スプレッドシートの共有リンク、管理用のURLを、画面、説明、公開プロジェクトに埋め込まないでください。
- 学校や先生、友人の個人情報、成績、名簿を、テストデータにしないでください。
- 第三者のロゴ、写真、商標、キャラクターを使う場合は、権利を確認します。
- アプリを削除しても、つないでいたスプレッドシートやデータベースにデータが残る場合があります。削除の条件を確認しましょう。
- 未成年の場合、公開、販売、収益化については保護者と確認してください。

## 商用化するときの考え方

ノーコードは、サービス固有の画面設計やワークフローに依存しやすく、乗り換えに時間がかかることがあります。商用化を目指すなら、次のように考えると安全です。

- ノーコードで**需要を検証**し、利用者が増えた段階で、有料プランの費用を負担できるか判断する。
- または、コードで静的なフロントエンドなどに**移行する計画**を持つ。
- 画面の構成、データの項目、ワークフローは、文書にして残す。データはCSVなどに書き出しておく。
- 試作の段階で、他人の機密情報、顧客名簿、売上データを預からない。収益化の約束はしない。
